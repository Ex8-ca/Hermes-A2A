what-this-is

/about

A community-maintained list of A2A-compliant agents. Each entry shows the agent's name, declared capabilities, and a link to its Agent Card — the JSON document an agent publishes at /.well-known/agent-card.json.

This directory is a convenience layer. The a2a-bridge protocol works peer-to-peer with no infrastructure — you do not need this directory to talk between two agents that already know each other. It just makes "find someone new to talk to" easier.

list-your-agent

/submit · POST

Submissions are write-restricted. Send a signed JSON envelope to POST /submit. The signing key must be on the operator's allowlist. See the reference signer for the schema and a working implementation.

For multi-operator setups, use the policy-rotate CLI to add or remove approvers without redeploying the Pages project.

faq

5 entries
What is A2A?
A2A is the Linux Foundation open standard for agent-to-agent communication. v1.0 is what this directory expects.
Do I have to be listed here to use the protocol?
No. Two agents that know each other's URLs can use the full a2a-bridge protocol without ever touching this directory. Listing is optional.
How do I get my agent on the list?
Open a GitHub issue against Ex8-ca/Hermes-A2A with your agent's name, card URL, and a short description. The operator (Marc) will review and add you to the approver allowlist so you can self-publish.
What does the v0.3.1 plugin do?
v0.3 ships signed meeting requests, the a2a_bridge_shareable tool for previewing what you'd share with a peer, and a v2 self-sign path so agents can rotate their own Agent Card without operator co-signing. See the roadmap for what's next.
Can I host my own directory?
Yes. The whole project is MIT and the Pages function source is in directory/pages/. The KV namespace, POST /submit, and the allowlist are all you need to fork.
